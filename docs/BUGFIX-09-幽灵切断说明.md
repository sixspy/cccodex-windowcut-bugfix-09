# BUGFIX-09 幽灵切断说明（封存件，当日不得改口）

> 封存日期：2026-11-21
> 缺陷：同一关闭窗被连点物化，`materialize_svc` 同代无去重，台账出现两条
> `status='成功'` 行；旧成功行成为幽灵金额源，污染对账。
> 约束：页面沿用、登录不动、SQLite 文件不换仓（仍是 `data/app.db`，只做幂等迁移）。

## 一、正确性口径（二择一，已择定，禁止混用）

**择定：甲路径 —— 已有成功物化则拒绝再插（二次插入拒绝）。**

- 同一 `(window_id, generation)` 只允许一条 `status='成功'` 的物化行。
- 重复物化请求：台账**零增**，HTTP `409` 拒绝，并写一条
  `materialize_duplicate_reject` 重复审计（含 window_id / generation / 既有行 id）。
- 数据库层用部分唯一索引
  `ux_materializations_success_per_generation ON materializations(window_id, generation)
  WHERE status='成功'` 作硬保证；即使应用层咨询锁失效，第二次插入也会被
  `sqlite3.IntegrityError` 拒绝，同一事务回滚后补记重复审计。

**乙路径（新单入库、同事务作废旧单）明确不采用**：本修复的新写路径中不存在
"插新单 + 作废旧单"的事务，不允许甲乙混用。

## 二、甲路径下"作废标"为何仍存在（不构成混用）

`status='作废'` 只用于**历史幽灵数据的一次性切断**，不用于任何新写请求：

- `init_db()` 幂等迁移：对每个 `(window_id, generation)` 内多于一条的历史
  `成功` 行，保留最早一条为有效，其余物理行**不删除**、原地改标 `作废`，
  并写 `materialize_ghost_cutoff` 审计（记录被切断的行 id 与原因
  "幽灵偏了：同代多条成功，按甲路径保留最早一条"）。
- 新请求永远走拒绝，不会产生新的作废行；作废行不参与对账取值、不计入看板。
- 判定边界：作废标是对**已落库脏数据的纠偏**，不是对新请求的处理策略；
  新请求的策略只有"成功插入"或"拒绝"两种，故与乙路径无涉。

## 三、并发口径（台账锁 + 争用条）

- 物化台账锁键 `materialize:{wid}`，在事务内先占锁再查重/插入。
- 两人同时同插同代：后到者 `try_acquire` 失败，**先提交争用登记再抛 409**，
  保证 `contention_log` 争用条不随回滚丢失；后到者不写任何业务行、不写业务审计。
- 同持锁者的连点（前端双击同一用户）靠甲路径查重 + 唯一索引拒绝。

## 四、五处同态（同一不变量的五个面）

| 面 | 表现 |
|----|------|
| 台账列表 | `GET /api/materializations` 同代仅一条 `成功`，历史幽灵显示 `作废` |
| 作废标 | 历史幽灵行 `status='作废'`，物理保留可审计 |
| 重复审计 | 拒绝再插写 `materialize_duplicate_reject`；幽灵切断写 `materialize_ghost_cutoff` |
| 对账取值 | 物化侧只取同代唯一 `成功` 行（`ORDER BY id ASC LIMIT 1`），幽灵/作废行不得进入对账 |
| 争用条 | 后到者在 `contention_log` 留一条 `争用`，提交后再 409 |

## 五、"偏说明"边界

只改文档/说明而无写路径修复与失败测试的交付，视为"幽灵偏了"：拒绝合入，
并在审计中以 `materialize_ghost_cutoff` / `materialize_duplicate_reject` 的
payload 原因字段保留"幽灵偏了"字样留痕。本修复含复现夹具、两红失败测试与
写路径改动，不属于偏说明交付。

## 六、明确不做

- 不做前端防抖替代后端正确性（前端页面不动；防抖即便存在也只是体验层）。
- 不换 SQLite 文件、不改登录与会话、不改表的既有列语义（仅新增 `generation`
  列并回填窗口代际）。
- 不物理删除任何历史台账行。
